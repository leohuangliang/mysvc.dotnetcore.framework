<execution>
  <constraint>
    ## .NET开发技术约束
    - **框架版本约束**：必须使用LTS版本的.NET框架，确保长期支持和稳定性
    - **编译器约束**：必须通过编译器的所有警告和错误检查，代码必须能够成功编译
    - **运行时约束**：必须考虑目标运行环境的资源限制（内存、CPU、网络）
    - **安全约束**：必须遵循OWASP安全编码标准，通过安全扫描工具检查
    - **性能约束**：API响应时间不超过2秒，数据库查询优化，内存使用合理
    - **兼容性约束**：必须与现有系统和第三方服务保持兼容性
  </constraint>

  <rule>
    ## .NET开发强制规则
    - **代码规范强制**：必须严格遵循C#编码规范和团队约定的代码风格
    - **异常处理强制**：所有可能抛出异常的代码必须有适当的异常处理机制
    - **资源释放强制**：所有实现IDisposable的对象必须正确释放，使用using语句
    - **异步编程强制**：I/O密集型操作必须使用async/await模式，避免阻塞线程
    - **单元测试强制**：所有业务逻辑代码必须有对应的单元测试，覆盖率不低于80%
    - **代码审查强制**：所有代码提交必须经过同行评审，通过后才能合并到主分支
    - **版本控制强制**：必须使用Git进行版本控制，提交信息必须清晰描述变更内容
  </rule>

  <guideline>
    ## .NET开发指导原则
    - **SOLID原则优先**：优先应用单一职责、开闭、里氏替换、接口隔离、依赖倒置原则
    - **DRY原则**：避免重复代码，通过抽象和封装提高代码复用性
    - **KISS原则**：保持代码简单明了，避免过度设计和不必要的复杂性
    - **性能优先考虑**：在设计阶段就考虑性能影响，选择合适的数据结构和算法
    - **可测试性设计**：编写易于测试的代码，使用依赖注入和接口抽象
    - **文档化重要决策**：对重要的技术决策和复杂的业务逻辑进行文档化
    - **渐进式重构**：持续改进代码质量，及时处理技术债务
  </guideline>

  <process>
    ## .NET开发标准流程

    ### Phase 1: 需求分析与设计
    ```
    1. 业务需求理解
       - 与产品经理/业务方确认功能需求
       - 明确非功能性需求（性能、安全、可用性）
       - 识别技术约束和限制条件

    2. 技术方案设计
       - 选择合适的.NET技术栈
       - 设计系统架构和模块划分
       - 设计数据库结构和API接口
       - 评估技术风险和制定应对策略

    3. 开发计划制定
       - 任务分解和工作量估算
       - 确定开发里程碑和交付时间
       - 分配开发资源和角色职责
    ```

    ### Phase 2: 开发环境准备
    ```
    1. 开发环境搭建
       - 安装Visual Studio或VS Code
       - 配置.NET SDK和相关工具
       - 设置数据库连接和测试数据
       - 配置代码质量检查工具

    2. 项目结构创建
       - 创建解决方案和项目结构
       - 配置NuGet包管理
       - 设置项目依赖关系
       - 初始化Git仓库和分支策略

    3. CI/CD流水线配置
       - 配置自动化构建
       - 设置自动化测试执行
       - 配置代码质量检查
       - 设置自动化部署流程
    ```

    ### Phase 3: 核心开发实施
    ```
    1. 数据层开发
       - 设计和创建数据模型（Entity）
       - 配置Entity Framework DbContext
       - 实现Repository模式或直接使用EF Core
       - 编写数据访问层单元测试

    2. 业务逻辑层开发
       - 实现领域模型和业务规则
       - 创建服务类和业务逻辑
       - 实现数据传输对象（DTO）
       - 编写业务逻辑单元测试

    3. API控制器开发
       - 创建Web API控制器
       - 实现RESTful API设计
       - 添加输入验证和异常处理
       - 配置API文档（Swagger）

    4. 横切关注点实现
       - 实现日志记录（Serilog/NLog）
       - 配置依赖注入容器
       - 实现认证和授权
       - 添加缓存和性能优化
    ```

    ### Phase 4: 测试与质量保证
    ```
    1. 单元测试编写
       - 使用xUnit/NUnit编写单元测试
       - 使用Moq进行依赖模拟
       - 确保测试覆盖率达到要求
       - 编写测试用例文档

    2. 集成测试实施
       - 编写API集成测试
       - 测试数据库交互
       - 测试第三方服务集成
       - 性能测试和负载测试

    3. 代码质量检查
       - 运行静态代码分析工具
       - 检查代码规范遵循情况
       - 进行代码审查
       - 修复发现的问题和技术债务
    ```

    ### Phase 5: 部署与监控
    ```
    1. 部署准备
       - 配置生产环境参数
       - 准备数据库迁移脚本
       - 配置应用程序设置
       - 准备部署文档

    2. 生产部署
       - 执行数据库迁移
       - 部署应用程序
       - 验证部署结果
       - 执行冒烟测试

    3. 监控和维护
       - 配置应用程序监控
       - 设置日志聚合和分析
       - 配置性能监控和告警
       - 建立运维响应机制
    ```
  </process>
